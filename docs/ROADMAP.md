# Roadmap

AtReady expands trust only after the preceding local boundary is proven.

## v0.1: deterministic local router

- Versioned private inventory and project contracts.
- Empty personal initialization plus TTY-only guided Quick Add, preview-first resource listing,
  advanced addition, complete same-ID replacement, and exact-ID removal through typed flags or
  versioned argv-safe declarations where applicable.
- Init-generated revision privacy nonces that blind exact revision/backup hashes against hidden-note
  guessing while remaining outside normal output and routing state.
- Target-scoped backup listing/inspection; exact-byte rollback that is preview-first,
  exact-revision and plan-token bound, protected by a private safety backup, atomically replaced,
  and post-replacement verified with durability uncertainty reported; and explicit exact-ID,
  one-backup-at-a-time deletion whose approval and plan token bind the active revision, selected
  backup, complete validated backup set, and separate apply, with an additional explicit override
  for the last backup, post-unlink verification and durability reporting, and no automatic
  retention policy.
- Target-scoped append-only operation manifests with canonical hash-linked prepared/outcome events,
  sequence ordering, unknown-history genesis adoption, and no trusted-time or signature claim.
- Explicit, read-only synthetic demo inventory with route opt-in and visible labeling.
- Bounded validation and sanitized routing snapshots.
- Pure deterministic routing, complete dispositions, and inert handoffs.
- Read-only route comparison that reports only assignment and gap changes between a baseline and
  one alternative project or constraint set.
- Public synthetic game, web, and creative evaluations.
- Read-only, fail-closed filesystem case-semantics validation before every backup-namespace use:
  Darwin canonicalizes physical spelling, non-Darwin POSIX requires case-sensitive identity, and
  Windows requires case-insensitive identity.
- No broad/automatic or provider discovery, telemetry, connector, or saved-resource execution for
  project work. One
  separately authorized built-in-profile executable location check is allowlisted, non-executing,
  proposal-only, and writes no inventory. Optional fixed-argument version inspection requires a
  second authorization and makes no claim about the external program's side effects.
- Separate previewed recovery for missing or safely readable invalid active targets, including
  exact-source binding and private quarantine of displaced invalid bytes.
- Conversation-first guided host onboarding: Assisted Setup is the default, may queue a supplied
  list by name, proposes editable catalog labels, and collects identity, strengths, readiness,
  unit-aware capacity, safety, and conservative-default acceptance in one plain-language card.
  Advanced Setup remains explicit. Both preserve one-resource recap/preview/apply authorization,
  grouped actual defaults, truthful intake status, and later complete same-ID enrichment.
- Provider-specific onboarding kits remain inert catalog data. The CodeRabbit kit adds
  researched workflow-mode proposals, tailored readiness/capacity questions, and exact
  `coderabbit`/`cr` executable aliases without inspecting an account, contacting CodeRabbit, or
  running a review. The compact OpenCode kit adds planning-relevant terminal, delegated CLI, and
  desktop/IDE workflow proposals plus model-provider-governed capacity guidance without inspecting
  configuration, authentication, billing, or account state. Dated model-routing suggestions now
  cover Cursor Composer 2.5, Cursor-hosted Grok 4.5, OpenCode's temporary DeepSeek V4 Flash Free
  option, and standalone Grok 4.5 without copying catalog prose into scores or inspecting live model
  availability. Cursor, Claude Code, Google
  Antigravity, and GitHub Copilot extend the same planning-only pattern. Cursor intentionally omits
  unsafe generic-basename discovery; Gemini CLI is deferred for new consumer setups because Google
  transitioned those users to Antigravity. Aider and Windsurf remain later candidates after beta
  evidence shows whether another provider-flexible CLI or editor profile adds distinct planning value.
- Explicit metadata semantics: billing and best/avoid remain non-routing descriptions, while a
  resource's declared approval prerequisite is preserved in every selected handoff without
  granting execution authority.

## v0.2: observed outcomes

- Append-only local outcome events with provenance.
- Bounded performance adjustments and staleness warnings.
- Subscription review candidates only after a documented evidence threshold.
- Export, clear, correction, and migration paths for the local ledger.

## Open-source beta gate

- Keep the CLI as the public product and the Codex skill as an optional conversational adapter.
- Give a new user one short source install, one safe synthetic demo, and one understandable path to
  their first personal route.
- Keep the public README focused on the idea, first use, trust boundary, and feedback. Preserve the
  detailed storage, recovery, routing, release, and plugin contracts in their dedicated documents.
- Run the full test, lint, package, README-rendering, and synthetic installed-wheel checks from the
  exact public candidate.
- Publish only reviewed source. Do not include private inventories, account information, generated
  personal plans, beta-access history, or release credentials.
- Treat the first public users as the practical beta. Prioritize setup friction, confusing output,
  recommendation usefulness, and repeat use over new providers, connectors, or routing features.
- Add a PyPI install only after the exact package/release lane is ready and independently verified.
- Revisit a public plugin-directory submission only if users want it and the supported-surface path
  is proven. Plugin packaging never grants broader permissions or execution authority.
- Design and prove previewed nonce migration/rotation and safe independent-clone handling before
  claiming in-place recovery for legacy unblinded or nonce-exposed private inventories.

## Next local hardening slices

- Previewed nonce rotation remains distinct from supported re-entry of root annotations into a
  newly initialized lineage.

## v0.3: consented provider discovery

- Named-provider inspection of authentication, live quota/capacity, and availability only after a
  provider-specific permission and threat review.
- CodeRabbit authentication observation remains deferred until an exact supported CLI version has
  reviewed synthetic and separately authorized live fixtures for its undocumented
  `auth status --agent` JSON shape, failure modes, redaction, and possible auto-update/network/write
  effects. Exit status or generic JSON validity must never be treated as authentication proof.
- Sanitized environment-variable names only where a named integration requires them.
- Provenance, timestamp, and confidence on every observed fact.
- No credential values, recursive home scans, generic connector, or inferred billing claims.

## Later: optional connectors and execution

Add connected actions only where they materially improve the product. Keep recommendation,
authorization, credential access, and execution separate. Require least privilege, destination and
data previews, explicit approval for consequential actions, and an auditable local record.
