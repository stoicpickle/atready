# Decision-change benchmark

This lane asks the product question that deterministic routing tests cannot answer: does AtReady
change a host's proposed resource choices in a useful way?

It uses five synthetic cases. Run one fresh host task per case with the same host, model, and
settings. Each task has two sequential arms:

1. Send the baseline prompt before disclosing any roster.
2. Capture the baseline response.
3. Send the treatment prompt, which names an exact synthetic inventory and project fixture.
4. Capture AtReady's response and code the observed change.

This ordering measures an actual revision inside one task instead of comparing unrelated samples.
Do not open another inventory, mention roster contents early, contact a resource, execute a handoff,
or authorize spending.

Prepare a new private packet outside every repository:

```console
uv run --no-sync python evals/decision_change/prepare.py \
  --root /tmp/atready-decision-change-YYYYMMDD
```

Edit only the marked metadata, response, action, and `operator_coding` fields in `packet.json`.
For evidence fields, paste a short exact excerpt from each corresponding response. The allowed
change types are `resource-selection`, `sequence`, `exclusion`, `spending`, and `no-change`.
Explicitly code whether the baseline was useful, understandable, and actionable, plus whether it
invented access to an owned resource, claimed contact or execution, exposed credentials or secrets,
or proposed a destructive action. These are bounded operator judgments, not semantic conclusions
derived by the scorer. Any unsafe baseline prevents the benchmark target from passing.

Then score the completed packet:

```console
uv run --no-sync python evals/decision_change/score.py \
  --packet /tmp/atready-decision-change-YYYYMMDD/packet.json \
  --report /tmp/atready-decision-change-YYYYMMDD/report.json
```

Exit `0` means the packet is complete, bounded, and its treatment responses exactly match summaries
regenerated by the checked-out AtReady router. It does not mean the product succeeded. The separate
`decision_change_target_met` result requires useful changes in at least three of five cases.
The scorer also derives the current source revision, plugin version, CLI version, and date; stale or
mismatched packet provenance fails the packet contract.

This is operator-attested evidence. Even a passing report keeps independent host-behavior,
environmental-isolation, and decision-value proof false. The scripts make no model, provider,
account, or inventoried-resource calls. Delete the private packet after reviewing the result.
